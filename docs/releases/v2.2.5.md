## No more duplicate Windows downloads

The v2.2.4 release published four Windows assets where there should have been two. Each pair had the **same SHA256** — the same file under two names:

```
EPUBShelf-2.2.4.exe          3fda18cb…   ← electron-builder (spaces → hyphens)
EPUBShelf.2.2.4.exe          3fda18cb…   ← action-gh-release (spaces → dots)
EPUBShelf-Setup-2.2.4.exe    5301b747…   ← electron-builder
EPUBShelf.Setup-2.2.4.exe    5301b747…   ← action-gh-release
```

It was never an `artifactName` problem: there were **two publishers**. The CI build jobs export `GH_TOKEN`, so `electron-builder` detected the tag and published by itself (`artifacts will be published reason=tag is defined`) — the `release` job then published the same files again. Both of them rewrite the spaces in the default names, which is why the twins differ only in separator.

### Fixed

- **Build jobs no longer publish** — `electron-builder … --publish never`. The `release` job is the single publisher.
- **Explicit, space-free names** — per-target `artifactName` in `package.json`: `EPUBShelf-Setup-<version>.exe` for the NSIS installer and `EPUBShelf-<version>.exe` for the portable build. The earlier attempts failed because `${target}` is not an electron-builder macro (only `productName`, `version`, `arch`, `ext`, `os` and `channel` are).
- **Only release files are uploaded as CI artifacts** — `upload-artifact` used to upload the whole `dist/` (75–78 files, ~200 MB per Windows job, including `win-unpacked/` and `linux-unpacked/`). It now uploads the `.AppImage`, `.deb`, `.dmg`, `.exe`, `.zip`, `.blockmap` and `latest*.yml` files only.
- **GitHub Actions bumped** — `checkout@v7`, `setup-node@v7`, `upload-artifact@v7`, `download-artifact@v8`, `action-gh-release@v3`. All run on Node 24, which silences the Node 20 deprecation warnings on every run.

### Verified

- A real Windows build was run locally (electron-builder 24.13.3 under wine) with `--publish never`: the output contains exactly `EPUBShelf-Setup-2.2.5.exe`, its `.blockmap` and `EPUBShelf-2.2.5.exe` — two distinct names, no twins.
- `build` config validated against electron-builder's `scheme.json` (`validateConfig`).
- `npm test`, `npm run lint` and `npm run i18n:validate` pass.
- This release itself is the end-to-end check: the asset list should contain one `EPUBShelf-Setup-2.2.5.exe`, one `EPUBShelf-2.2.5.exe` and no dotted or hyphenated twin.
